### Эндпонинт `/team/deactivateMembers`

Этот эндпоинт предназначен для массовой деактивации пользователей в рамках одной команды. Помимо установки флага `isActive = false` для указанных пользователей, он также выполняет безопасное переназначение всех открытых Pull Request'ов, которые были на них назначены.

**Security**: `Admin`

**Тело запроса**:
```json
{
  "team_name": "payments",
  "users": ["u1", "u2"]
}
```

#### Логика работы:

Вся операция выполняется в рамках одной транзакции для обеспечения атомарности и целостности данных
Данная операция идемпотентна
1. **Поиск кандидатов**: Определяется пул потенциальных ревьюеров. В него входят все **активные** члены той же команды, которые **не попали** в список на деактивацию
2. **Поиск PR для переназначения**: Система находит все **открытые** PR'ы, где в качестве ревьюеров числятся деактивируемые пользователи
3. **Переназначение**:
    *   Для каждого такого PR определяется, сколько ревьюеров выбывает
    *   Из пула кандидатов подбирается необходимое количество новых ревьюеров
    *   Переданные пользователи снимаются со всех открытых PR, а новые назначаются
4. **Деактивация**: После успешного переназначения PR, у всех пользователей из исходного списка обновляется статус на `isActive = false`
Если на каком-либо этапе происходит ошибка, вся транзакция откатывается, и никаких изменений в базе данных не сохраняется

#### Возникшие проблемы
Дедлок при попытке деактивировать нескольких пользователей одновременно.
**Решение**: Сортировка списка пользователей по алфавиту перед началом транзакции для обеспечения последовательного порядка блокировок записей в бд + ретраи на такие транзакции.
